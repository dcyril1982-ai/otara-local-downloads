# Отара Local 2.3.6

Локальная программа для овцеводческого хозяйства: macOS 13+, Windows 10 x64 1809+ / Windows 11 x64 и Android 8+. Русский интерфейс, центральная база на компьютере, автономный учёт. После настройки обмена Android получает задания и передаёт факты через GitHub или Яндекс.Диск.

## Изменения 2.3.6

- «Бухгалтерия» оформляет документы по формам СП-20 (расход кормов), СП-24 (шерсть), СП-39 (приплод), СП-43 (взвешивание), СП-44 (привес), СП-47 (перевод животных), СП-54 (падеж, забой и прирезка), а также собственную универсальную форму хозяйства.
- СП-21 адаптирована для учета молока овец. 406-АПК, 410-АПК и 411-АПК предоставляются как исторические шаблоны: приказ, которым они были утверждены, отменен. Для их использования и для адаптированной/собственной формы программа хранит решение хозяйства об утверждении формы; это не объявление старого приказа действующим.
- Форма выбирается по виду факта. Доступны необходимые дополнительные графы, основание операции, сведения об ответственном, приказ о комиссии и участники. Недостающие реквизиты видны при проверке. Черновик нельзя принять за оформленный документ.
- В справочники номенклатуры включены ОКЕИ и подтвержденные коды ОКПД 2 с нормативными источниками. Можно уточнить классификацию и внутренний код позиции с указанием основания. Неоднозначный код не подставляется по догадке; ОКЕИ соответствует единице конкретной операции. ОКУД унифицированных СП задан каталогом; у адаптированного СП-21 отдельно обозначен код исходного образца. Пустые коды исторических АПК не выдумываются.
- В «Бухгалтерия → Формы и подписание → Автозаполнение» постоянные реквизиты хозяйства и ответственные лица настраиваются один раз, с уточнением для отдельных форм. При выборе бланка, сохранении черновика и команде «Дополнить / автозаполнить» программа использует настройки, карточки животных и исполненные операции. Уже введенные непустые значения, включая ноль, сохраняются. Неизвестные фактические показатели, ОКПО и счета не выдумываются; расход корма не подменяет утвержденную норму.
- Хранятся отдельные версии документов, основания исправлений и сведения об оформлении бумажного оригинала. Исправленный экземпляр связан с предыдущим. Повторная печать не переписывает исходник и не повторяет движение животных, расход материалов или выпуск продукции.
- Масса, количество, единицы измерения и ссылки на источники проверяются. Литры не превращаются в килограммы без подтвержденного пересчета, неподтвержденная предыдущая масса остается неизвестной. Перевод оформляется по выполненному перемещению, а не создает новое задание.
- Android получает справочные коды и настройки доступных форм для работы без связи. Работник своей роли может выбрать бланк, заполнить известные реквизиты, дополнительные сведения, участников комиссии и основание. Компьютер дополняет доступные исторические сведения и получает черновик для проверки и печати; ФИО и факт отправки не считаются электронной или собственноручной подписью.
- В первичном экземпляре, его печати и бухгалтерской выгрузке сохраняются снимки номенклатурных кодов, версии документов и связь с источниками. Изменение справочника и настроек не переписывает отраженные экземпляры. Самоучитель объясняет настройку автозаполнения, уточнение классификации, выбор формы, проверку реквизитов, подписи, исправления и передачу бухгалтеру.

Бумажный первичный документ оформляется с реальными подписями ответственных лиц. Программа не выпускает квалифицированную электронную подпись. Утверждение применяемой формы хозяйством и проверка бухгалтером остаются отдельными действиями.

## Обновление и сохранность

Устанавливайте поверх предыдущего приложения под той же учетной записью ОС. Обновление не создает новое хозяйство и не очищает данные: стадо, пользователи, настройки, папки данных и системные хранилища ключей сохраняются. Android 20306 обновляется поверх 20305 без удаления приложения и очистки данных; используется постоянный сертификат выпусков.

Перед первой записью новых структур первичных документов, утверждений форм, настроек автозаполнения (`primarySettings`) или нормативных реквизитов номенклатуры (`regulatory`) создается проверяемая копия `before-v2.3.6`; требование читателя повышается до 2.3.6. Ошибка резервирования отменяет запись. Такую базу нельзя открыть версией 2.3.5. Простое открытие хозяйства не повышает требование читателя. Прежние границы 2.3.2, 2.3.4 и 2.3.5 сохраняются; уже оформленные исторические документы и неподтвержденная очередь телефона не переписываются. Восстановление раннего архива — отдельная операция со сверкой последующих событий. Копия базы не переносит системное хранилище ключей на другой компьютер.
