# Отара Local 2.3.10

Локальная программа для овцеводческого хозяйства: macOS 13+, Windows 10 x64 1809+ / Windows 11 x64 и Android 8+. Русский интерфейс, центральная база на компьютере, автономный учёт. После настройки обмена Android получает задания и передаёт факты через GitHub или Яндекс.Диск.

## Изменения 2.3.10

В разделе «Отчёты → Подготовка ВетИС» появился мастер настройки тестовых реквизитов, подготовки собственной площадки и проверки сценариев Меркурия и Хорриота. Мастер показывает опубликованные операции шести сервисов Меркурия, фактические квитанции, недостающие условия и результат каждого проверяемого сценария. В настройках доступны официальные инструкции по получению тестового и производственного доступа. Создание собственной тестовой площадки и её связь с хозяйством оформляются отдельными проверяемыми запросами. Подтверждение площадки, предоставление полномочий и подготовка поднадзорного объекта Хорриота остаются действиями уполномоченного оператора ВетИС.

Ежедневный тестовый пакет выполняет разрешённые запросы чтения по сохранённому календарю десяти рабочих дней. Запуск и исход каждого обращения фиксируются в журнале. Программа возобновляет опрос принятой заявки, сохраняя её идентификатор; неизвестный результат не становится основанием для повторной отправки операции. Для запуска после закрытия окна используется фоновая задача центрального компьютера. Нужны включённый компьютер, сеанс пользователя, сеть и доступ к защищённым реквизитам. Фоновая проверка справочника не заменяет реальное оформление ВСД и подтверждение производственного процесса за день.

Готовность Меркурия проверяется по десяти завершённым рабочим дням, по доле ошибок MERC для каждого типа операции за сутки и по отсутствию APL/APLM. При новом периоде прежние ошибки сохраняются. Выбранные сценарии требуют проверенного государственного результата. Исключённые из плана операции видны как непроверенные и не получают право производственной отправки. Для Хорриота применяется собственный набор проверяемых операций; правило десяти дней Меркурия ему автоматически не приписывается.

После готовности плана администратор сохраняет отдельные производственные реквизиты, указывает полученное разрешение оператора ВетИС, выполняет запрос чтения и явно включает рабочий обмен. Программа не выдаёт государственные полномочия самостоятельно. Каждый производственный запрос проходит проверку и подтверждение; ранее поданные заявки можно продолжать опрашивать независимо от состояния нового мастера.

Операции ВетИС доступны из связанных рабочих разделов: приёмка и возврат, включая пакетную полную приёмку/полный возврат нескольких ВСД, — из стада, перемещений и бухгалтерии; регистрация, маркировка и группы Хорриота — из карточек и групп животных; выполненные ветмероприятия — из раздела здоровья; убой и производство — из производства; складские остатки и инвентаризация — из склада и бухгалтерии; отгрузка, транспорт и регионализация — из перемещений. Выбор официальной номенклатуры, контрагентов, площадок и адресов связан с соответствующими справочниками. Открытие формы само по себе ничего не отправляет.

Реальными квитанциями тестового API подтверждены обработка канонических имён сервисов, чтение справочников с версиями записей, создание собственной тестовой площадки и её связь с хозяйством, а также изменение номенклатуры. Изменение ветеринарных сведений партии и транспортных точек проверено локально по официальным XSD и синтетическим ответам; живые проверки этих операций ещё требуют доступных складских записей и ВСД. Несовпадающий UUID ответа отклоняется; сбой государственного сервиса не считается успешной проверкой. Исправлено определение местного календарного дня при учёте фактов: сегодняшние операции принимаются после полуночи, а будущие даты по-прежнему отклоняются. Исходные квитанции завершённых операций, ВСД, история попыток отправки и программа апробации защищены независимым журналом. Восстановление более старой копии этого хозяйства сохраняет уже зарегистрированные государственные результаты и неизвестные исходы отправок.

Выпуск программного обеспечения не означает получение продуктивного доступа ВетИС. Государственная приёмка требует собственного допуска, доступных тестовых объектов и реальной апробации хозяйства. Найденные отказы тестового сервера и неподтверждённые сценарии отражаются в протоколе, а не заменяются успешными отметками.

Самоучитель объясняет приёмку, склад, производство, отгрузку, регионализацию, операции Хорриот, официальные справочники, черновики и проверку статуса. Документальный приёмочный вес виден на компьютере и Android; государственные запросы выполняются на центральном компьютере с защищёнными реквизитами.

## Обновление и сохранность

Устанавливайте обновление поверх предыдущей версии под прежней учётной записью ОС. Не удаляйте приложение Android и его очередь. Стадо, пользователи, настройки и системные хранилища ключей сохраняются. Перед первой записью защищённой истории создаётся архив; такие данные требуют Отару 2.3.10 или новее. Прежняя версия не должна открывать базу с новым журналом. Архив базы не переносит системные секреты на другой компьютер автоматически. Самоучитель и руководство Android обновлены.

Проверки CI по опубликованным схемам и синтетическим ответам сами по себе не подтверждают государственные полномочия. Приёмка конкретной 1С, закрытых форматов СЕЛЭКС и конкретных весов остаётся отдельной. Публичное чтение ВСД не является авторизованным обменом или гашением. Физическое управление отсутствующими автоворотами выключено до аппаратного испытания.
