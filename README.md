# Отара Local 2.3.1

Локальная программа для овцеводческого хозяйства: macOS 13+, Windows 10 x64 1809+ / Windows 11 x64 и Android 8+. Русский интерфейс, центральная база на компьютере, автономный учет. После настройки обмена Android получает задания и передает факты через GitHub или Яндекс.Диск.

## Изменения 2.3.1

- 27 рабочих справочников: поиск по названию и синонимам, защита от дублей, добавление внутри формы без потери введенных данных, архив и восстановление. Прежние документы, партии и остатки сохраняются.
- 43 кормовые позиции для российских хозяйств, со ссылками на источники Росстандарта, аграрного вуза и отраслевые материалы. Цельное и дробленое зерно, жмых и шрот, разные формы жома разделены. Необычный фактически используемый корм можно добавить отдельно.
- Препараты выбираются по реальным данным хозяйства с указанием формы и единицы. В настольных формах прихода препаратов и топлива выбор позиции с другой единицей при введенном количестве требует подтверждения; автоматического пересчета количества нет. Каталог не назначает лечение или рацион.
- Исправлены пустые списки и объяснения в «Приплоде и выбытии», расходе кормов, препаратов и других формах. Сначала регистрируется исходное событие, затем оформляется первичный документ. Карантинное исследование выбирается из плана конкретного эпизода.
- Источники открываются в системном браузере. Разрешены HTTP/HTTPS-ссылки без встроенных учетных данных; текущее окно программы сохраняется.
- В Android доступны поисковые справочники из пакета хозяйства. Старые черновики сохраняются, отсутствующий выбор требует уточнения. Несовместимые категории и единицы продукции блокируются на телефоне и центральном компьютере.
- Самоучитель дополнен порядком работы со справочниками, единицами и пустыми списками; всего 52 урока.

## Обновление и сохранность

Устанавливайте поверх предыдущего приложения под той же учетной записью ОС. Сохраняются стадо, пользователи, настройки, папки данных и системные хранилища ключей. Android обновляйте без удаления приложения и очистки его данных; используется постоянный сертификат выпусков.

Перед первой записью с требованием читателя 2.3.1 создается аварийная копия `before-v2.3.1-…`. Ошибка ее создания отменяет запись. База после перехода требует 2.3.1; версия 2.3.0 блокирует ее открытие и изменение. Для возврата к старой программе нужна совместимая копия до обновления; последующие факты в нее не входят. Копия базы сама по себе не переносит системное хранилище ключей на другой компьютер.
